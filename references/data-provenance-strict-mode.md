# 数据溯源严格模式（CPMS / 产物字段通用）

> 来源：2026-10-19 业务对实单 `BJXQ260704002` 的纠正 ——
> **「你编写的东西必须是通过客户所提供的文件得到的，你不可以创建错误信息，没有就是没有。」**
> 本文是这条要求的可执行版本；案例复盘见 `cpms-real-sample-bjqx260704002.md`。

---

## 1. 规则

`CPMS`（以及任何由 agent 手写的字段）**只允许写客户提供的文件（附件 / 邮件正文）里出现过的事实**。

- 每句话必须能指到**客户文件的一个位置**（单元格 / 段落）；指不到的删掉。
- 确认单、ERP 导出、历史单据、别的客户档案、行业惯例 —— **都不是来源**。
- 业务侧要补的信息（指定供应商、纸箱强度、料号、供料责任方、内部编号）走 ERP 字段或邮件回复。

## 2. 五种「柔性造数」（看起来合理，其实是在编）

| # | 模式 | 例子 | 正确做法 |
|---|---|---|---|
| 1 | **区间补整** | 客户写 `50-60 stickers per title`，我们写 `每款60张` | 照抄 `每款50至60张（客户原文）` |
| 2 | **泛称具体化** | 客户写 `polybag`，我们写 `OPP自粘袋0.05mm`；`price sticker` 写成带料号 `ZW80/G6552` | 客户没给材质/料号就不写；只翻译不改信息量 |
| 3 | **空栏补合理值** | 附件没给窗口尺寸，我们写 `窗口约100*100mm`；没给颜色数写 `8种颜色` | 空就是空。要尺寸就回邮件问，不要「按经验估一个」 |
| 4 | **未标注的换算/估算** | 客户写 `1.25mm bookblock`，我们按表换算成 `1500g`；厚度按「宁厚勿薄」取值 | 换算只能用于**我们自己的 ERP 字段**（且有表可查），原文表述进 CPMS 时保持原样 |
| 5 | **跨单据搬运** | 从业务确认单/上一单/别的客户档案里复制「他们通常这么做」 | 客户没写就不写，哪怕确认单里有 |

> 「合理」不是免责理由：客户没说的，我们写了，就是替客户做决定 —— 报错价、做错货的起点。

## 3. 判定流程（30 秒版）

1. 逐句读 CPMS，每句问：**这句我能指到哪个单元格/段落？**
2. 指得到 → 保留；指不到 → 删（或标记「待客户确认」写进给业务的邮件，不写进 CPMS）。
3. 客户原文没给量词的（`570 gemstone stickers`）→ 用中文量词（`570颗`）可以，数字不许变。
4. 客户原文语义未明（页脚数字、内部代号）→ 放 `备注` 并注明「客户原文 / 语义未明」，**不许猜含义**。

## 4. 机械门禁

```bash
uv run ./scripts/cpms_content_audit.py --cpms <ERP.json> --source <客户原始文件>
# 退出码 = 无出处条目数，必须 0
# 同时列出「客户文件有、CPMS 没写」→ 人判是真漏还是有意不写
```

它覆盖：数字、单位（`gsm≡g`、计数词按数字溯源、数字与单位分处两格也算）、料号/编号。
覆盖不到的是**语义级替客户做决定**（模式 2 的部分情况）—— 那部分靠本文第 2 节的清单人工过。

## 5. 与其它规则的关系

- 与「CPMS 写法规范 v2」（骨架 / 槽位 / 闭集词表）不冲突：v2 管**怎么排**，本文管**能写什么**。
- 与「客户偏好表 / `erp_fixed`」不冲突：那些是**ERP 字段**的固定口径，不是 CPMS 内容。
- 与「宁可留空不许猜」（档案层）同源：那条约束脚本；本文约束 agent。
